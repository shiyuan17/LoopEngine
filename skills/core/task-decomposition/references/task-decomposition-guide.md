# Task Decomposition Guide

任一公共契约、Schema 或数据模型迁移/兼容变更，混合重构与行为修改，或探索和实施无法在一个连续任务稳定完成，都要求拆分。否则统计多个模块、顺序依赖、可并行单元、独立验收阶段、多层验证五项软信号：0-1 直接实施，2-3 拆分实施，4+ 建立带依赖的 Task DAG，并说明依据。

输出一个描述最终结果的 Goal Brief、节点表、依赖图、并行批次、关键路径、里程碑、风险、回滚点和第一个 Ready 节点。每个节点必须能被一个 Agent 连续完成、独立验证和独立交付，只包含一个主要行为目标；验证属于节点，不创建笼统测试节点，不重复规划已完成工作。

每个节点固定包含目标、依赖、输入、精确项目相对写入范围、资源锁、非目标、约束、验收、验证命令/人工判据、产物、风险、回滚和并行性。检查环、虚假依赖、范围冲突、共享契约多方写入、缺失 fan-in 和未覆盖验收；发现问题返回阻塞或修订后的 DAG。

为每个节点生成宿主无关的可复制提示词：先重读当前工作区和依赖证据，只执行一个依赖已满足的 Ready 节点，修改仅限节点范围；验证失败、范围漂移、依赖不成立或需要再拆分立即停止并报告。禁止提前执行后继、自动派发、提交、推送、生产/共享数据写入和凭据输出，除非用户另行授权。

最终输出至少包括：拆分判定、Goal Brief、未决项、任务表、DAG、并行批次、关键路径、里程碑、主要风险和第一个 Ready 节点，以及每个节点的执行提示词。该 Skill 不自动创建 Goal、修改文件或选择下一个 Ready 节点。
